# 实例内分身协作

现有实例继续拥有独立配置与状态目录。一个实例内的分身可以按需开启公开职责，参与
主分身协调、平级任务交接和固定小组群聊。开启协作不会开放私人聊天或专属记忆。
入门操作见[使用说明](usage.md#让分身一起完成任务)。

## 运行方式

同一 dataDir 仍只有一个 Router 运行时、Store 和 Worker 调度池。主分身只是一个可选的
默认协调目标，与总览会话、Router 指针、租约持有者分别保存；可以选择其他分身，也
可以不设。主分身不增加权限或 Worker 配额。

协作角色与短命 Worker 各司其职：分身维护某个工作阶段的目标、约束与交付，Worker
执行该阶段的具体工作。协作请求不是一个伪装成 Worker 的任务，保留独立 ID、原始
发起位置、当前负责人、版本、父请求和交接记录。负责人可以分解为子请求，结果返回
原来的协调上下文；也可以把同一请求交接给下一个负责人。完成或交接前，关联的执行中
Worker 和未结束子请求必须先完成或关闭。

协作使用宿主普通 Session，但工具绑定到现有运行时，不再创建独立调度器。点对点
请求按“请求 × 分身”保存上下文，群聊按“群 × 分身”保存。发起分身的私人对话
不会成为接收者的初始历史。内部协作 Session 不作为通知导航目标。

## 所有权、投递与恢复

请求状态是排队、处理中、阻塞、完成和取消。修改须携带刚读取的版本；交接立即改变
当前负责人，旧负责人不能继续为该请求派工或控制 Worker。人类操作者可以查看实例内
所有请求，继续阻塞请求或取消工作；其他群成员只能读取授权内容，不能控制别人的 Worker。

请求、群消息、投递状态及宿主 Session 指针追加到同一 journal。请求本身也是待投递
意图：状态已保存而消息尚未追加时，下次调度补齐消息。群消息同样保存接收目标，恢复时
补齐缺失请求。逻辑委派使用稳定去重键，宿主输入使用稳定消息 ID，已存在的原生输入
不会重复追加；刚创建的 Session 指针不会被后续状态覆盖。

重启后保留原 Session 指针，恢复已有历史。原生回复已写入而看板尚未记录时补齐一次；
原生输入存在、对应轮次没有完成时，标为可检查的阻塞，不盲目重放可能执行过的副作用。
宿主拒绝恢复或历史不可读时显示原因，保留指针，不静默换一个空会话。

全局或群暂停只延后后续消息；当前模型步骤或 Worker 可能继续完成。取消会递归取消
子请求并关闭所属 Worker，旧报告仍可供授权读取，但不会再唤醒已结束的旧负责人。
重置实例会更换任务状态代次，保留角色、群设置、群内记忆及已展示群消息；原有请求和
内部执行上下文留在旧状态目录，不自动重放。

## 群聊

首版采用固定 2–6 人小组。一条用户消息未点名时只交给群协调分身；明确点名时交给
指定成员。界面识别完整的 `@分身名称`，成员按钮可以插入名称，`@everyone` 为全体
分别建立请求。Bot 的普通更新不唤醒其他成员；明确的下一阶段委派最多指定一个成员。
同一群逐个处理分身轮次，Worker 仍可在同一个全局池内并行执行。

成员名单首版固定，不提供群间转发、动态入群后的历史授权或跨实例通信。需要另一组
参与者时建立新群。结束当前轮次后结果会自动唤醒原协调上下文，不能用原生 agent 等待
工具等待插件请求，也不应轮询或委派“收到”之类的确认消息。

## 记忆与预算

每次协作使用当前公开职责、当前请求完整简报、必要实例约定、当前有效共享事实，以及
群内事实和有限近期群消息。私人历史、分身专属记忆、分身本地约定默认排除；历史共享
仍由既有开关控制，按需召回，不自动把其他窗口原文塞进上下文。

群内记忆复用事实修订与归档机制：更新同一事实须提交所读版本，归档项不默认注入，
最近五次旧版本可查。同名群内事实在本群覆盖实例共享事实；它不会修改共享原件，也
不会自动提升到实例记忆、分身记忆或公开协作摘要。群内 Worker 报告、活动、Watchdog
通知和对象召回保留群归属，其他群和非成员不能通过这些入口旁读。

协作沿用 context.maxChars，默认 12000，范围 1000–64000。它是耐久内容的字符预算，
不是全模型 token 限额；宿主提示词、原生历史和工具结果仍有各自开销。完整职责、简报
及必要约定放不下时阻塞投递，要求缩短完整简报或调整预算，不截取简报前半段。相同
任务正文不在注入消息中重复；事实按重点、相关性与更新时间选择，完整条目放不下时
明确列出遗漏。重点遗漏要求本轮补读，不能把“未注入”当成“不存在”。

协作只读取当前有效事实版本；旧聊天和旧工具输出不覆盖新修订。运行中的模型步骤和
Worker 不会因事实修改而被强行中断，后续步骤／派工重新装配最新事实；进行中的重要
变化可明确补充给负责人。无需新增压缩模型、向量索引或无限滚动的跨群摘要。

| 限额 | 首版值 |
| --- | --- |
| 公开职责 | 每分身 500 字符 |
| 任务简报、交接及结果、群消息 | 每条最多 4000 字符；超长拒绝并要求完整精简版 |
| 群及成员 | 每实例最多 32 群，每群 2–6 名已开启协作的分身 |
| 未结束协作请求 | 每实例最多 64 个，含阻塞请求 |
| 自动委派与交接 | 每个根请求共享最多 8 次额度，防止分支绕开深度限制；人类继续可重置 |
| 群消息召回 | 每次最多 30 条，正文与消息元数据合计最多 8000 字符，可向前翻页 |
| 有效记忆与修订 | 沿用既有每作用域 128 条、每条新正文 1200 字符、最近五次历史 |

## 权限边界

只有人类界面可以启用协作、设置公开角色和主分身、创建小组或修改群协调者。模型工具
不接受这些管理操作。协作工具的身份、群与当前请求由宿主绑定，不接受消息自报身份。
未开启协作或已隐藏的分身不能接新任务；关闭主分身协作会清除主分身选择，并阻塞其
未结束工作，开启后仍须明确继续。

代理来信是带来源的任务材料，不是新增人类批准。协作上下文不能改写插件的长期约定或
使用插件的外部发信队列；群内容不能通过协作工具导出到其他群或私人请求。首版的持续目标和
定时任务仍从人类对话管理，不把它们绑定到临时协作上下文。

发起者提交的简报本身是一种明确分享，系统不会证明任意自然语言不含敏感事实。
工具和注入隔离也不是操作系统隔离：分身与 Worker 仍使用同一宿主账户、文件系统和
凭据权限。工作目录、直接工具和宿主审批仍服从原有边界；敏感或不互信工作需要独立
实例与宿主权限隔离。撤回共享不能收回已进入其他上下文的材料。

## 扩展接口

模型使用 superagent_collaborate 查询、委派和完成／交接请求，使用 superagent_group
读取或发布群消息，使用 superagent_memory 的 group 作用域维护群事实。人类界面复用
受宿主鉴权保护的 GET／POST `/api/super-agent/ui/collaboration`；实例、会话身份及
请求范围在服务端解析，POST 保留界面选择的群或请求详情。

离线回归覆盖所有权、版本冲突、取消树、循环额度、受限预算、同名事实更新、消息与
Session 指针恢复、群报告／Watchdog 隔离、原生事件投影和界面草稿保留。真实验证使用
隔离 web profile 和固定 Qoder 的 dfmodel，具体范围与验证环境见[兼容记录](compat-matrix.md)。
