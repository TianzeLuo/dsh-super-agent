# 记忆与上下文场景验证

2026-11-14 UTC，在 DSH 0.2.2-rc.3、WSL2、Linux Node 24.21.0 的隔离 web profile
验证。所有真实模型调用固定为 Qoder 的 dfmodel（宿主路由
[dsh-provider-qoder/dfmodel](https://github.com/mo-n/dsh-provider-qoder)）。
使用虚构事实与独立实例，不读用户真实聊天。原始会话、失败记录、证据文件和截图仅留本机。

## 场景与结果

| 场景 | 验证方法 | 结果 |
| --- | --- | --- |
| 长程事实更新 | 作者连续 60 轮新增 44 条普通背景，并穿插日期、负责人和审核条件修订、只读讨论、归档与恢复；自动预算 3000 字符 | 稳定名称始终只有一条当前记录，修订替换旧值；长程过程中及最终共 9 次独立读者核对，每次六个当前事实／隐私字段均符合预期 |
| 预算压力下的关键限制 | 普通记录超过预算，关键条件位于较长陈述末尾，明确准备完成不代表审核通过 | 日期、负责人、审核代码和禁止发布结论保留；普通资料有明确省略提示 |
| 新读者 | 新建没有作者聊天历史的主题，读取同一共享事实 | 六个字段全部正确，超过 30 条记录被省略，重点遗漏为零 |
| 冷启动 | 保留宿主与实例状态，停止并重启隔离宿主，再核对同一读者 Session | 最新日期、负责人、条件、归档失效和私有字段均正确；原会话身份保留 |
| 相关主题进展 | 在普通记录饱和时连续两次更新另一主题阻塞；要求读者只用自动上下文、不得调用工具 | 两次均回答最新阻塞，第二次不沿用旧值；原生记录确认读者轮次没有工具调用 |
| 旧格式长文本 | 将旧版约 3300 字符、末尾带禁止发布条件的文本迁移，在 3000 字符预算下读取 | 原始备份和全文完整，超长条目不被部分注入；模型按需读到末尾审核条件并保持禁止结论 |
| 最低预算与外部更新 | 自动预算 1000 字符，三个重点条目均放不下；两轮之间由操作者修改日期、负责人和审核条件 | 两轮均重新调用记忆读取，采用当轮新值；较长条目末尾的否定条件完整保留 |
| 编辑并发 | 应用内浏览器编辑草稿，同时由另一请求修订同一条目 | 草稿保留、保存停用；明确载入最新版本后才能修订，归档与恢复保留同一 ID |
| 界面 | 实际操作创建、编辑、共享范围、四项进展、修订历史、上下文预览 | 深浅色与 390×844 窄屏均检查，未见横向溢出；验证在应用内浏览器进行 |

原生会话审计确认隔离宿主的模型输出均来自指定路由；所检查的只读核对轮次没有记忆、
进展或约定写入，也没有派工。审计中的零运行错误不等于所有早期回答均正确，发现与
修正的问题列在下节。

## 对照与结论边界

对相同共享事实流做了一个受控对照：将按时间追加的事实文本取前 3000 字符，交给同模型
的普通新会话，不启用插件记忆，也不允许工具补查。四个关键字段中，对照正确 2 个，
新版完整条目选择正确 4 个。它说明此事实流中的前缀策略会漏掉后续修订与约束，
**不是旧版插件的完整端到端复跑，也不是多数据集统计结论**。

默认 12000 字符是可调整的工程起点；3000 和 1000 是压力测试设置，不证明任何一个
预算普遍最优。关键词相关性没有语义理解保证；不同名称下的矛盾事实仍需模型或用户
明确合并，不能把这些场景通过描述为一般长期记忆已被解决。

## 迭代中发现的问题

- 早期进展核对返回未知：当前问题还未进入选择逻辑，相关进展被普通记录挤出。
  对照原生宿主确认先组装、后 pre-step、再准入刷新的顺序；改为捕获当前认领的
  用户输入，动态内容在准入时重新选择，并补上相应接线回归。
- 宿主把时间和动态上下文也记为 user-role 消息；现按来源排除这些生成内容，避免它们
  覆盖用户问题或成为事实来源。新回归覆盖这两种原生消息形状。
- 复测曾复用相同结束标记，脚本误读上一轮答案；现每次请求生成唯一标记。原始失败
  记录保留，修复后的两次进展回答另行核对，没有用旧结果代替新请求。
- 初始评分把正确回答中提及的旧日期判为失败；最低预算评分也曾拒绝代码后附带的
  正确“未通过”说明。现核对结构化当前值和独立的能否发布字段，代码要求唯一且正确，
  不把历史解释或正确限定语当作事实错误。
- 空上下文的界面分支曾返回无法展开的值；修复后补上空列表回归，并复查真实页面。
